# Профиль проекта для ревью

## Что это

- Официальный модуль доставки ApiShip для OpenCart: расчёт доставки в чекауте, карта ПВЗ (Яндекс JS API 3.0), выгрузка заказов в ApiShip, ярлыки/акты, cron-экспорт и импорт статусов.
- Распространяется архивами и ставится владельцами магазинов на их собственные серверы. Серверной части у проекта нет, обновление — только новым релизом, который магазин ставит сам.
- Четыре независимых пакета в одном репозитории: `2.1`, `2.3`, `3.x` (OCMOD: `upload/` + `install.xml`) и `4.x` (расширение OpenCart 4.1, `install.json`). `mods/` — готовые архивы для сторонних шаблонов, не исходники.
- Без composer, без фреймворка, без сборки фронтенда: PHP в структуре OpenCart (controller/model/language/view), Twig/tpl-шаблоны, один ванильный JS-скрипт карты с jQuery магазина.

## Что такое реальный сбой

- Покупатель не может оформить заказ: способ доставки ApiShip не появляется, карта не открывается, выбранный ПВЗ не попадает в заказ, «Продолжить» проходит без выбранного ПВЗ или не проходит с выбранным.
- Неверная цена или срок доставки в чекауте либо на пине/в карточке ПВЗ; у точки показан не тот тариф или не та служба.
- Фатальная ошибка PHP на витрине или в админке, в том числе только на одной из поддерживаемых версий PHP.
- XSS: данные из API ApiShip (названия служб, статусов, точек, адреса, трек-ссылки) попали в html чекаута, карты или админки без экранирования. Данные API считаются недоверенными.
- Cron-эндпоинт принял GET или ключ в адресе; cron-ключ попал в html админки; действие с заказом выполнилось без прав администратора на нужный маршрут.
- Скрипт карты разошёлся между пакетами, либо после обновления модуля браузер берёт старый скрипт/стили из кеша.
- Память и трафик на больших городах (сотни и тысячи точек): повторная загрузка одной точки, квадратичные проходы по точкам на каждое действие пользователя.

## Радиус поражения

- Сбой в чекауте = магазин теряет заказы до выхода и ручной установки следующего релиза. Откатить удалённо нельзя.
- Окружения не контролируются: PHP от 5.6-совместимого синтаксиса до 8.3, разные шаблоны и модули чекаута (Simple, Простор, ShowCase, Smartstore, UltraStore, UniShop), чужие OCMOD-правки поверх тех же файлов.
- `ApishipMap.open` и формат ответа карты — контракт для доработанных шаблонов магазинов; его изменение ломает чужой код и обязано быть в CHANGELOG.

## Планка для находок

- Находка должна быть существенной, а не просто верной: назвать сценарий, в котором покупатель, администратор или cron получает неверный результат.
- Шум здесь: отсутствие типов, DI, PSR-автозагрузки, namespace в пакетах 2.x/3.x; стиль кода ядра OpenCart; «вынесите в общий модуль» для кода, продублированного между пакетами; отсутствие PHPUnit и CI; пожелания переписать на современный JS-стек.
- Правка в одном пакете без такой же правки в остальных — существенна, если дефект или поведение общие для пакетов.

## Где лежат правила проекта

- `README.md` — совместимость, установка, cron, права, карта ПВЗ, команды проверок.
- `dev/oc4/README.md` — стенд OpenCart 4.1, сценарий приёмки, что умеет mock API (в том числе служба `evilhtml` и статус `evilstatus` для проверки экранирования).
- `Makefile` — все проверки: `make lint`, `make test`, `make test-js`, `make lint-oc3`, `make test-oc3`. CI нет, эти команды и сценарий приёмки — и есть проверка перед релизом.
- `CHANGELOG.md` — пользовательский, на русском, кратко; каждое видимое изменение поведения и каждое изменение контракта должно быть там.
- `CLAUDE.md`, `AGENTS.md`, `CONTRIBUTING.md` в репозитории нет.

## Намеренные конвенции — не дефекты

- Пакеты `2.1`, `2.3`, `3.x` пишутся в синтаксисе PHP 5.6: без `??`, типов свойств, стрелочных функций. Пакет `4.x` — PHP 8.3. Нарушение в 2.x/3.x — дефект, «устаревший» синтаксис — нет.
- Скрипт карты ПВЗ одинаков во всех четырёх пакетах и лежит четырьмя копиями. Дублирование намеренное (пакеты ставятся по отдельности); дефект — расхождение копий, его ловит `make test-js`.
- Имя архива `apiship.ocmod.zip` для 4.x фиксировано: установщик OC4 берёт код расширения из имени файла.
- Адрес скрипта и стилей карты содержит версию модуля — это сброс кеша браузера, а не лишний параметр.
- Cron: только POST, ключ в заголовке `X-Apiship-Key` или POST-поле `key`; ключ в адресе отклоняется намеренно.
- Справочники, точки и расчёты кешируются в кеше OpenCart, а не в сессии покупателя.
- Поиск по адресу на карте: при отсутствии у ключа доступа к Search API строка поиска ищет по адресам ПВЗ — это задуманный фолбэк.
- Калькулятор API может вернуть один и тот же `tariffId`/`tariffName` несколько раз с разной ценой, сроками и `pointIds` (зоны). Агрегация идёт по записи, а не по `tariffId`; «дедупликация по tariffId» — ошибка, а не упрощение.
- Юнит-тесты — самописные раннеры `dev/oc3/tests/run.php`, `dev/oc4/tests/run.php` и `dev/oc4/tests/map.js` без фреймворков.

## Языки

- PHP (два диалекта, см. выше), ванильный JavaScript в браузере, Twig и `.tpl`, XML OCMOD (`install.xml`), Python только в `dev/oc4/mock-api`, shell и Docker только в `dev/`.
- Всё под `dev/` — стенд и тесты, в релизные архивы не попадает: планка для него ниже, чем для кода пакетов.
